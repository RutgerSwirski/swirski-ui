# Web accessibility and interaction audit

This is a source and interaction review against the [WAI-ARIA Authoring Practices patterns](https://www.w3.org/WAI/ARIA/apg/patterns/) and [WCAG guidance for content on hover or focus](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html). The packed Playwright fixture exercises Chromium, Firefox and WebKit. Its axe checks target serious and critical violations in representative states.

| Component family | Keyboard and accessibility contract | Verification and remaining checks |
| --- | --- | --- |
| Dialog, Drawer, Navbar mobile menu | Move focus into the modal, contain Tab and Shift+Tab, make background inert, lock body scroll, dismiss only the top overlay on Escape, restore focus to a valid opener. Supply a title or explicit label. | Packed nested, initially open and sibling modal flows cover stack order, portal focus and scroll restoration. Mobile tap covers Dialog and the mobile menu. Check screen-reader modal boundaries, including mobile drawers. |
| Popover | Trigger exposes popup state; Escape dismisses and returns focus to the trigger. Nonmodal content can contain interactive controls. Give dialog-style content a name. | Packed nesting with Select and DropdownMenu. Check Tab order for standalone popovers and announcement of popup contents. |
| DropdownMenu | Enter, Space or down arrow open at the first enabled item. Up arrow opens at the last item. Arrows wrap, Home/End jump, typing matches enabled item labels, Tab and Shift+Tab dismiss and continue from the trigger, Escape dismisses and restores trigger focus. Disabled items are skipped. | Packed focus, typeahead, dismissal and axe checks. Check announcements with icon-only or application-provided menu labels. |
| Select | One focusable combobox with active-descendant navigation. Arrows, Home/End and typeahead explore options, Enter/Space commits, Escape and Tab dismiss. Required empty values block submission. Use a native label or an explicit accessible name. | Packed keyboard, shrinking options, submission, validation and reset. Check announcement of highlight versus committed value and invalid state on desktop and mobile screen readers. |
| Tooltip | A stable description is associated with its focusable trigger. Focus or pointer hover reveals supplementary text. The pointer can move into the popup. Escape hides it while focus stays on the trigger. | Packed hover/focus and dismissal. Use a single trigger that forwards DOM props, preferably with `asChild`. Keep interactive controls and essential instructions outside tooltips. Check description timing and touch screen readers. |
| Tabs, Accordion | Tabs use one tab stop with arrows and Home/End. Accordion uses native details/summary activation with Space or Enter. | Packed keyboard samples and existing Tabs tests. Check screen-reader reading order in dynamically replaced panels. |
| Button, Navbar desktop, Breadcrumb, Pagination, AppShell, HeroActions | Native button/link semantics when rendered as their default element. Name icon-only controls, label navigation regions, and preserve current-page state where applicable. Composed children must forward semantics and refs. | Source review and existing composition/navigation tests. Consumers own landmark naming and navigation behavior in composed layouts. |
| InputField, Field, Checkbox, Switch, ThemeToggle, RadioGroup, Slider | Prefer the native input interaction. Preserve visible labels, hint/error associations and checked/value state. Give standalone controls a name and label radio groups. | Representative named controls in axe fixture, plus packed checkbox and switch activation. Check validation announcements and high-contrast focus indicators for all input shapes. |
| CursorPicker and CursorDock | Radio picker has one tab stop and wrapping arrow selection. Dock keyboard focus reveals its picker, Tab enters it, Escape closes it. | Packed picker navigation. Check cursor selection announcements and avoid using cursor changes as the only signal. |
| Alert, Toast, Progress, Loader, Skeleton | Status and progress APIs convey meaning without requiring focus. Name progress indicators, use loading states sparingly, and avoid announcing decorative skeletons. | Source review. Manually check repeated live messages, progress updates and focus around dismissible notifications. |
| Card, Badge, Avatar, typography, layout, background and image primitives | Primarily presentational. Polymorphic interactive usage must preserve the underlying button or link, meaningful names and image alternatives. | Source review and existing composition checks. Interactive styling alone does not establish keyboard semantics. |

## Manual checks before claiming accessibility conformance

- With NVDA and Firefox or Chrome, verify the label, selected value, active option and form validation feedback for Select.
- With VoiceOver and Safari, including iOS, verify nested dialog boundaries, dismissal order, focus restoration and tooltip descriptions.
- Test real high-contrast themes and keyboard focus on custom variants. The automated forced-colours check covers a Chromium menu trigger.
- Test at 200% zoom and with actual touch input. The packed touch fixture exercises a narrow viewport, not assistive touch exploration or hardware.
- Verify live announcements, application-supplied names and errors, and consumer-composed children in the final UI. Automated axe scans do not establish full accessibility.
